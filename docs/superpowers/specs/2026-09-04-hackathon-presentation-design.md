# 모두의 한국어 3분 30초 발표 자료 설계

## 목표

심사위원이 첫 30초 안에 실제 이주민 학부모 사례와 불편한 순간을 이해하고, 60초 live demo에서
user flow 전체를 확인하게 한다. 발표는 `필요성 → 사회문제 → 서비스 소개 → user flow와 demo`를
먼저 닫은 뒤 LLM, 구현 범위, Codex 검증을 부가 근거로 제시한다.

## 결과물

- 배포 가능한 single-page HTML slide deck
- 16:9, keyboard navigation, 발표자용 timing 표시
- live demo URL을 새 tab으로 여는 버튼
- slide별 speaker notes를 HTML 내부에 포함
- 총 6장, live demo 60초를 포함해 3분 30초

PPTX는 만들지 않는다. HTML은 현재 FastAPI app과 독립된 정적 파일로 두고, 배포 환경에서는 같은
origin의 `/` 또는 설정한 demo URL을 연다.

## slide별 설계

### 1. 전화 한 통을 앞둔 학부모

사용자 장면 한 문장과 전화 아이콘만 둔다. 제품 설명과 통계는 넣지 않는다. 2026-09-04 사용자가
확인한 주변의 실제 사례를 개인정보 없이 `주변 이주민 학부모`로 소개한다. 이 학부모는 아이 학원을
두 달 쉬기 위해 전화해야 했고, 한국어 표현과 존댓말, 상대 질문에 즉시 답하기, 발음 전달을 모두
걱정했다. 사례에서 확인하지 않은 국적, 이름, 학원, 금액은 추가하지 않는다.

### 2. 생활의 결정은 실시간 한국어로 이루어진다

단일 사례를 전체 이주민의 경험으로 일반화하지 않는다. 전국 다문화가족 실태조사의 조사 규모와
장기 거주자 비율은 문제 대상의 규모와 지속성을 설명하는 근거로만 사용한다. 국립국어원 연구가
지적한 정규 집단 교육과 고정 시간 매체의 한계를 함께 제시한다. 마지막 10초에 `모두의 한국어는
내일 해야 할 대화를 오늘 10분 먼저 연습하는 AI 회화 도구`라고 소개한다. `10분`은 제품 가설로
표현하고, 출처 URL은 speaker notes에 남긴다.

### 3. 내일의 대화를 오늘 먼저 연습

하나의 수평 흐름으로 실제 demo contract를 보여 준다. 입력은 `아이 학원을 다음 달부터 두 달 쉬고
싶어요. 다시 다니려면 언제 연락해야 하나요?`라는 상황 음성이고, 출력은 `내일 쓸 세 문장`이다.
role-play 중 교정은 `어휘·문법`과 `발음 전달도` 두 축이다. 이 slide에서 demo 버튼을 열고 흐름을
그대로 시연한다.

### live demo

slide deck에서 demo 버튼을 눌러 배포된 앱을 새 tab으로 연다. 시연자는 학원 휴원 상황 음성,
한국어 첫 답변, 피드백, 같은 문장 재시도, 내일 카드까지 60초에 완주한다. 현재 app의 실제 동작과
고정 응답 또는 미완성 범위는 slide 5에서 구분한다.

### 4. LLM이 필요한 자리

LLM 역할을 세 개로 제한한다. 자유로운 생활 목표를 rehearsal schema로 바꾸고, 사용자의 답에 맞춰
질문과 도움을 바꾸며, 실제 대화에서 먼저 고칠 내용을 고른다. 현재 model 연결 여부와 실제 산출
범위는 구현을 다시 확인한 뒤 하단 disclosure에 정확히 표시한다.

### 5. 작동 범위와 검증

현재 code와 test를 다시 실행해 실제 동작, 고정 응답, 미완성 범위를 나눈다. 검증 건수만으로 신뢰를
주장하지 않고, 실패해야 하는 empty audio와 잘못된 state transition이 실제로 거부되는 양성 대조를
보여 준다. Codex 활용은 생성량보다 contract와 반례로 과장을 막은 과정에 초점을 둔다.

### 6. 내일 말할 수 있게

완벽한 한국어가 아니라 내일의 목적 전달이 성공 기준임을 한 문장으로 고정한다. 학원에서 시작해
학교, 병원, 직장의 다음 대화로 확장할 수 있음을 짧게 보여 준다. 마지막 문장은 `한국어 전체를 오늘
가르치려 하지 않습니다. 내일 꼭 해야 할 한마디를 오늘 자기 목소리로 끝냅니다.`로 끝낸다.

## visual system

- 제품과 같은 `#6046E8`, 흰색, 연한 보라색을 사용한다.
- `Noto Sans KR`, `Noto Sans SC`, system sans-serif 순서로 사용한다.
- title 48–64px, body 24px 이상을 기본으로 한다.
- dashboard형 card grid를 만들지 않는다. slide마다 한 장면과 한 주장만 둔다.
- 장식용 stock image는 사용하지 않는다. 제품 UI screenshot과 단순 typography를 중심으로 구성한다.
- 외부 통계와 연구 출처는 해당 slide의 notes에 기록한다.

## interaction과 fallback

- `ArrowRight`, `Space`, `ArrowLeft`로 이동한다.
- 현재 slide와 전체 slide 수, 발표 경과 시간을 작게 표시한다.
- demo URL은 query parameter 또는 상단 상수 한 곳에서 바꿀 수 있게 한다.
- demo가 열리지 않으면 slide 3의 제품 UI screenshot과 slide 5의 실제/fixture 범위로 발표를 계속한다.
- reduced motion 설정에서는 transition을 제거한다.

## 검증

1. browser에서 16:9와 1280×720 viewport를 각각 render한다.
2. 모든 slide의 overflow와 최소 font size를 확인한다.
3. keyboard navigation과 demo link를 직접 누른다.
4. 발표 대본을 stopwatch로 재서 3분 30초 이내인지 확인한다.
5. 출처 문구와 현재 구현을 `docs/product-brief.md`, `CODEX_LOG.md`, test code에 대조한다.
6. fixture를 실제 AI 결과처럼 읽는 문구가 없는지 검색한다.

## 범위 밖

- 새로운 제품 기능과 실제 LLM 연결
- 모바일 발표 화면
- login, history, settings
- 검증하지 않은 사용자 인터뷰 결과
- fixture 점수를 실제 사용자 성과로 해석하는 주장
