# 내일의 한국어 — 역할 분담과 파일 경계

## 원칙

같은 파일을 동시에 수정하지 않는다. 구현 중 판단이 필요한 경우에도 상대 파일을 직접
고치지 않고, 이 문서의 계약과 새 문서·새 디렉터리로 경계를 만든다.

## 역할

| 담당 | 책임 | 산출물 |
| --- | --- | --- |
| 준현님 (Sol) | 제품이 브라우저에서 끝까지 동작하도록 프론트엔드·백엔드·오디오 흐름·통합을 구현 | 앱 셸, 1:2 리허설 UI, 마이크 입력, API 라우팅, 실행 방법, 통합 데모 |
| 유현님 | AI가 무엇을 판단하고 어떻게 응답하는지 설계·검증 | 모델 선택, 프롬프트, 중국어 상황 해석, 역할극·교정 워크플로우, JSON 계약, AI 테스트 시나리오 |

## 파일 소유권

### 준현님 소유

- 제품 실행 코드 전체: 프론트엔드, 백엔드, 서버 진입점, 의존성·실행 설정
- 음성 녹음·재생, 화면 상태, API 호출·에러 표시, 데모 실행 스크립트
- `README.md`의 실행 방법과 `CODEX_LOG.md`의 구현·통합 기록

유현님은 위 파일을 직접 수정하지 않는다. AI 응답을 받는 위치와 API 형식이 바뀌어야 하면
`docs/ai-api-contract.md`의 변경 제안으로 먼저 전달한다.

### 유현님 소유

- `ai/`: 모델 설정, 프롬프트, JSON 스키마, AI 전용 검증·샘플 입력
- `docs/ai-correction-spec.md`: 어휘·문법·발음 교정 원칙과 점수 해석
- `docs/ai-api-contract.md`: 백엔드가 소비할 AI 요청·응답 계약

준현님은 `ai/`의 내부 로직을 수정하지 않는다. 앱은 계약에 정의된 요청을 보내고 응답만
렌더링한다.

### 잠긴 공동 기준 문서

- `AGENTS.md`
- `docs/product-brief.md`
- `docs/brainstorm.md`
- `DESIGN.md`

이 문서는 합의된 제품 결정을 담는다. 수정이 필요하면 먼저 채팅으로 합의하고, 한 사람이
수정한 뒤 다른 사람은 재확인만 한다.

## 통합 계약

유현님은 AI 결과를 화면 코드와 분리된 JSON으로 제공한다. 준현님은 다음 두 단계로
통합한다.

1. AI 없이도 화면이 도는 고정 JSON으로 1:2 리허설과 피드백 상태를 먼저 완성한다.
2. 계약이 확정되면 같은 JSON 모양의 실제 AI 응답으로 교체한다.

AI 계약에는 아래 정보가 반드시 있어야 한다.

- 중국어 상황 확인 질문 또는 확정된 상황 맥락
- 상대 역할의 한국어 질문
- 사용자의 재시도용 완성 한국어 문장
- 어휘·문법 피드백 목록과 간체 중국어 설명
- 발음 전달도 점수, 네 단계 상태 문구, 집중 단어, 간체 중국어 안내
- 다음 행동: 재시도 또는 다음 질문

## 작업 순서

1. 유현님: 모델·STT·발음 점수 산출 방식과 AI JSON 계약을 확정한다.
2. 준현님: 고정 JSON으로 전체 데모를 먼저 브라우저에서 작동시킨다.
3. 유현님: 실제 AI 입력 1건을 계약대로 반환하는 최소 워크플로우를 만든다.
4. 준현님: 실제 응답을 연결하고, 중국어 입력 → 한국어 답변 → 즉시 교정 → 재시도 점수 갱신을 확인한다.
5. 준현님: 통합 결과와 검증을 `CODEX_LOG.md`에 기록한다.

## 상호 전달 방식

- 유현님 → 준현님: 계약 파일 경로, 샘플 요청 1개, 기대 JSON 1개, 변경 이유.
- 준현님 → 유현님: 호출 위치, 요청·응답 오류, 브라우저에서 재현한 입력과 화면 증거.
- 계약이 바뀌면 유현님이 새 버전을 만들고, 준현님은 기존 계약과 호환되는지 확인한 뒤 반영한다.

## 이번 데모의 완료 기준

사용자가 중국어 음성으로 결석 상황을 말하면, 화면은 중국어 맥락을 보여 주고 담임 역할의
한국어 질문을 제시한다. 사용자의 한국어 답변 뒤에는 어휘·문법과 발음 전달도가 분리되어
보이며, 고친 완성 문장을 재시도했을 때 새 발음 점수가 갱신된다.
